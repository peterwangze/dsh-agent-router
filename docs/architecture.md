# 多模态路由平台：整体分析与设计

> **定稿 v2**（已确认：多模态开/关两种状态——开启即接管用户模型配置，
> 包装路由显示「原名 + 多模态」；后端链复用专业 agent 列表；视觉先锋不
> 新增工具；按里程碑逐条提交）。
>
> 定位：`dsh-agent-router` 的核心不是 vision——vision 只是**先锋验证模态**。
> 平台目标是支撑任意模态扩展：视觉识别、语音识别、实时语音对话、视频识别与
> 生成、图片生成等全链路能力；主（纯文本）agent 始终是"大脑"，模态能力以
> 透明、原生、可迭代的方式挂接。

## 1. 目标与原则

- **原生体验**：模态内容（粘贴截图等）走 DSH 原生链路（粘贴 + 回车），
  界面按原生机制显示原件；不接管 composer、不改宿主代码。
- **大脑不动**：主模型的文本轮在模型、上下文、成本上完全不受影响。
- **模态可插拔**：新增模态 = 新增「管线处理器 + 改写器 + 工具包 + 后端链
  配置」，不动平台骨架（不变量见 §3.3）。
- **证据可验证**：模态内容中的文字是**不可信证据**；工具可精确定位/裁剪/
  对比，答案按内容缓存，支持像素级闭环。
- **安全**：不损坏用户数据；产物只写会话工作区；凭据走 credentials 缝。

## 2. 事实基础（DSH 0.1.0-rc.7 已逐条验证）

| # | 缝隙 | 用途 |
| --- | --- | --- |
| F1 | `ctx.llm.registerAdapter([provider], adapter)`（公开 API） | 注册自有路由与适配器；适配器完全掌控序列化与委托 |
| F2 | prompt 准入读"当前选中模型"的 `inputModalities` | 包装路由声明含 image 即放行；准入是模型级而非会话级 |
| F3 | 会话日志与模型输入是两层：UI 读日志，适配器收 `options.messages` | 日志保留模态原件（UI 原生显示）、模型输入层改写，互不污染 |
| F4 | `agent/request` / `agent/pre-step` / `agent/request-error` 瀑布 | 每请求改路由、改进入步骤的消息、处理请求失败 |
| F5 | 工具注册 + `tool.call.toolview` + `conversation.chat.*` 节点槽 | 模态工具集 + 专用展示卡 |
| F6 | `attachments`（内容寻址、批量保存、限额、校验） | 模态原件持久化与去重 |
| F7 | `files` 参数分发 + fs 服务 + 工作区 | 音频/视频/任意文件的既定通路（无准入问题） |
| F8 | composer 仅接受图片块（粘贴/拖拽，MIME 白名单） | 音频/视频不能以消息块进 composer → 只能走工作区文件（录音/落盘按钮 → 路径进消息） |
| F9 | subagents、settings/credentials/typert、`llm/adapters-updated` 事件 | 委派、配置、远程、热更新 |
| F10 | `ctx.llm.registration(provider).adapter`、`llm.listProviders()` | 惰性获取原适配器做委托；注册的路由自动出现在模型选择器 |
| F11 | `sessions.provide` 标准套件（useInput/inputActions）、客户端 `conversation` 服务 | composer 附件入口（可选增强） |
| F12 | composer 链槽选择器仅见 `{interactions, session}`；交互帧仅宿主私有通道可铸造 | 插件**不能**按草稿状态接管 composer；原生输入条不可替换 |
| F13 | `registerAdapter` 对已注册 provider 抛 `DUPLICATE_ADAPTER`；注册 handle 只能注销自己 | **原文本组无法从选择器移除**——接管形态是"包装路由 + 自动切换选中"，原组保留为逃生通道 |
| F14 | `agentDefaultModel.currentSelection/saveSelection`（默认模型）、`session.selectModel`（会话选中）、`serializeImageAdmission`（切换与准入串行化） | 两层接管：默认模型（新会话）+ 当前会话；开启瞬间切换 → 贴图零竞态 |

**已验证参考模式**（dsh-vision-router v1.5.2 源码）：twin 包装路由声明
`['text','image']` 过准入（F1/F2）；`rewriteImagesDeep` 在适配器序列化层把
图片块改写为文本证据，**日志保留原件**（F3）；文本大脑按需调用视觉工具
（F5）；后端链逐级降级 + 缓存 + 降采样；本插件独立实现同构模式，不复刻其
免费端点/工具全集。

## 3. 核心架构（五层，模态无关）

```
┌───────────────────────────────────────────────────────────────┐
│ L1 准入包装层  Admission Wrapper                                │
│   每 provider 一个包装路由（<provider>-router，显示             │
│   「原名 + 多模态」）：resolveModel 镜像原元数据并按已启用模态   │
│   聚合声明（['text', ...modalities]）；stream() 文本轮委托      │
│   原适配器、含模态块轮先经 L3 改写再委托。                      │
│   接管：开启 → 默认模型 + 当前会话自动切到包装路由（零竞态）；  │
│   关闭 → 恢复原 provider。原文本组保留（F13 硬约束）。          │
├───────────────────────────────────────────────────────────────┤
│ L2 模态输入管线  Modality Input Pipeline                        │
│   统一入口：消息块(image) / 工作区文件(audio/video/任意)          │
│   职责：鉴权、限额、魔数识别、缓存寻址、降采样、证据缓存           │
├───────────────────────────────────────────────────────────────┤
│ L3 模型输入改写层  Model-Input Rewrite Registry                 │
│   模态 → 文本证据 的注册表（image→描述/工具标记；                │
│   audio→转写文本；video→抽帧描述+时间轴…）                      │
│   只改模型输入，绝不写日志（F3）；多模态并存 = 各改写器各改各块  │
├───────────────────────────────────────────────────────────────┤
│ L4 模态工具包  Modality Tool Packs                              │
│   按真实场景按需注册（vision 先锋当前无需新工具：               │
│   route_agent 通用路由已覆盖）；基础设施（后端链、降级、        │
│   超时、缓存、产物、展示卡）随首个真实需求落地                   │
├───────────────────────────────────────────────────────────────┤
│ L5 后端链解析  Backend Chains                                   │
│   复用现有 agent/账号/池/CLI 体系：每个模态 = 有序后端链          │
│   （主 agent + 降级 agents），逐级失败切换（池逻辑同构）          │
└───────────────────────────────────────────────────────────────┘
```

### 3.1 各层职责与依赖

- **L1**：两种状态。**多模态关**：零介入（不注册、不改模型、不接管）。
  **多模态开**：为每个已启用 provider 注册包装路由 `<provider>-router`
  （显示「原名 + 多模态」，用户一眼确认钩子生效）；`resolveModel` 镜像
  原元数据并按已启用模态聚合声明；`stream()` 无模态块的消息原样以原
  provider 委托（文本轮零开销）、含模态块经 L3 改写后委托。
  **接管**：默认模型（`agentDefaultModel.saveSelection`，覆盖新会话）与
  当前会话（客户端 `session.selectModel`）自动切到包装路由——切换发生在
  开启瞬间而非贴图瞬间，贴图 + 回车零竞态；关闭时恢复原 provider。
- **L2**：模态处理器接口 `{ detect(input), limits(), evidence(id, ctx) }`。
  image 处理器当前仅接入 attachments 缓存寻址；降采样、证据缓存、
  audio/video 处理器（工作区文件、转码/抽帧、分片）按真实场景按需落地。
- **L3**：注册表 `modality → rewrite(block, ctx) → text[]`（`MODALITY_ENTRIES`，
  新增模态 = 追加条目，聚合声明与按块分发自动支持并存）。image 改写器
  当前落地最小形态：静态工具标记（→ route_agent/includeImages，复用既有
  视觉通路）；证据缓存（描述文本）升级为注册表时按需实现。改写覆盖嵌套
  tool-result（原文本适配器会递归拒绝）。
- **L4**：工具包 = `name 前缀 + 一组 defineTool`，按真实场景按需注册；
  vision 先锋无新增工具。共用 `ToolHost`（后端链解析/降级/超时/产物/
  展示卡）随首个真实工具需求落地。
- **L5**：后端链 = 有序的**专业 agent 引用**（复用现有 agent 配置体系）+
  每模态默认链（未配置时）。当前视觉通路即单 agent 引用（route_agent）。
  失败分类（认证/限流/超时/上下文/网络）与冷却熔断在出现多后端需求时
  落地，复用现有池统计结构。

### 3.2 关键不变量（防架构腐化）

1. **日志 = 原件，模型输入 = 改写文本**；转换只发生在 L3 单点。
   气泡显示的内容只来自会话日志（确定性）；模型输入层**零模态痕迹**——
   模态块整体删除、不留任何替换/占位文本（任何非用户文本都会被大脑当
   "用户说的话"复述——提示词约束不了模型输出，只能靠输入构造消除），
   模态证据全部由 system 层标记承载；`route_agent` 的附件从日志层读取
   （`selectAttachments → session.deriveMessages`），不依赖模型输入层。
2. **模态是插件化扩展点**：L2/L3/L4/L5 都是注册表；平台骨架（L1 适配器、
   ToolHost、配置/统计）不感知具体模态。**激活单位是模态改写器，不是
   包装路由**——单一聚合包装路由承载全部已启用模态。
3. **后端链与"专业 agent"同一身份体系**：L5 引用 agent id，
   配置/统计/账号/池全部复用，不引入平行配置结构。
4. **接管可逆**：开启 → 切包装路由；关闭 → 恢复原 provider；原文本组
   永远保留为逃生通道（F13 硬约束，不可移除）。
5. **带图轮确定性整轮路由**：用户带图是确定性信号，绝不依赖大脑自觉调
   工具（实测大脑从不自觉）。本轮 provider/model 经 `agent/request` 瀑布
   直接切到视觉 agent 的模型——图片原生直传、视觉模型直接看图回答；
   文本轮与视觉 agent 缺失时保持默认配置。route_agent 工具按需作为
   文本轮内的补充（图生图等），system 标记只覆盖视觉 agent 缺失的兜底
   路径（图生图分流），且只标记当前轮最后一条 user 消息（历史图不重复
   标记）。

### 3.3 执行通路扩展（`agent.type` 作为注册点）

现有 `chat / agent / cli / image / speech` 类型成为执行通路注册表的初值；
新增通路（如 `realtime`）只新增实现，不改 `run()` 分发骨架。

## 9. 已确认决策（2026-08 确认）

1. **接管形态**：两种状态——多模态关 = 零介入；多模态开 = 直接接管用户
   模型配置（默认模型 + 当前会话自动切到包装路由，显示「原名 + 多模态」），
   用户看到的模型仍是自己选的、实际流量已过包装层。原文本组并行保留
   （F13 硬约束），作为逃生通道。
2. **后端链配置形态**：复用专业 agent 列表（agent id 有序数组 = 链，
   出现多后端需求时启用）。
3. **工具范围**：视觉先锋**不新增任何工具**——route_agent + L1 + 上下文
   附带 + toolview 已覆盖当前链路；后续工具按真实场景按需提出。
4. **节奏**：按 §7 里程碑逐条提交，测试全绿后立即提交。

| 断言 | 结论 |
| --- | --- |

**关键实现语义**（记录于测试注释，L1 实现必须遵守）：
- 适配器异常在 rc.7 被转换为终态 `finish` 错误块而非抛出；
  twin 的 `yield* llm.stream(...)` 委托会把错误块原样上抛给 agent-loop。
