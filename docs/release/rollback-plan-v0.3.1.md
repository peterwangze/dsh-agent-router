# v0.3.1 回滚方案（Rollback Plan）

| 项 | 值 |
|---|---|
| 发布版本 | v0.3.1（candidate） |
| 回滚目标 | v0.3.0（2026-08-29 tag `bb81abf`——GitHub Release + tarball 1,507,506B 在案可重装，EV-084） |
| 可逆性分类 | **可逆-低风险**——无 Schema 迁移、无数据格式变更、无依赖面变更（v0.3.1 产品段零触碰 package.json，两轮审查实采）；唯一行为面 = 转正语义（门控链移除/配置键废弃/UI 转正）+ 1 条 telemetry 事件 + 文档/注释——revert 机械性高于 v0.3.0（无交织 revert 约束） |
| 预计回滚时间 | 阶段一（push 前 abort）**分钟级 < 5 分钟**；阶段二（push 后 revert+版本面处置）**15–30 分钟**（含全量复跑）；阶段三（用户侧 junction 回退）**分钟级** |
| 关联文档 | `docs/release/release-checklist-v0.3.1.md`（第三步 + §冷装 runbook）/ `docs/release/version-plan-v0.3.1.md` §3.3（kill-switch 三层）/ `docs/release/feature-flags-v0.3.0.md` §4（关闭验证语义转正注记）/ `docs/release/rollback-plan-v0.3.0.md`（v0.3.0 语义先例——回滚目标版本行为参考） |

## 回滚触发条件（发布后 48h 观察期）

1. 出现 P0/P1 级新 bug（回归、崩溃、核心通路失效）；
2. **转正兼容承诺断裂**：v0.3.0 已登录账号升级后凭据保留/继续可用承诺失效（CHANGELOG 未发布段核心兼容承诺）；
3. 一键登录新登录链路回归（1455 回调 / 设备码降级 / 兑换链路）；
4. 宿主 dsh-* 再漂移致适配断裂（RISK-003——parity 复跑变红即触发；本版零依赖变更，触发概率面与 v0.3.0 相同）；
5. OpenAI 侧收紧升级（R-E1：client/端点/风控变化致通路不可用或风险升级）；
6. 用户主动要求回退。

> 与 v0.3.0 触发条件的差异：v0.3.0 条件④「统计落盘损坏且自愈失效」不列入本版——EVO-006/REL-004 零触碰 stats 域；保留①②③④⑤⑥一般性条款。**发布后 CHANGELOG 勘误惯例**沿用 v0.3.0 先例（post-release 修正单独提交留痕，不重写已发布节历史）。

## 回滚总览（三阶段——先止血再动代码）

| 阶段 | 窗口 | 动作 | 生效 | 耗时 |
|---|---|---|---|---|
| 一 | push 前（执行段任一步失败/叫停） | 中止执行序列 + 本地清理 | 本地面 | 分钟级 < 5min |
| 二 | push 后（已 tag/已 Release） | 代码层 revert + 版本面处置（前滚修复或回退重发——用户裁决） | 版本面 | 15–30min |
| 三 | 用户侧（安装态） | junction 开发树 checkout v0.3.0 / v0.3.0 tarball 重装 + 重启 | 单机面 | 分钟级 |

## 阶段一：push 前 abort（发布执行中失败/叫停——分钟级）

执行序列（version-plan §4 M-5：E-1 bump → E-2 复跑 → E-3 pack+冷装 → E-4 tag → E-5 push → E-6 Release）在 **E-5 push 之前**任何一步失败或叫停时，按已完成步骤逆向清理：

| 已完成步骤 | 清理动作 | 验证 |
|---|---|---|
| E-1 bump commit（含 CHANGELOG 收口/README 同步） | `git revert <bump-commit>`（**优先 revert 不用 reset**——保留历史留痕；仓内未推送无 force-push 顾虑） | `git log` 确认 revert 提交在案；package.json 回读 0.3.0 |
| E-3 pack + 冷装 | 删除仓库根 tgz；$tmp 临时目录清理（冷装 runbook 步骤已含零触碰校验） | 仓库根无 tgz 残留 |
| E-4 tag v0.3.1（本地） | `git tag -d v0.3.1` | `git tag -l v0.3.1` 为空 |
| E-2 复跑 | 无需清理（只读验证） | — |

**abort 窗口关闭点 = E-5 push 执行**。push 后进入阶段二。

## 阶段二：push 后代码层回滚（仓库侧——15–30 分钟）

### B-0 前置（顺序强制）

1. **先执行场景 A 止血**（kill-switch 关闭面——避免 revert 过程中缺陷面继续暴露）；
2. 评估缺陷范围：若缺陷可定位且前滚修复可行，**优先前滚**（B-3 选项 a）。

### B-1 revert 范围

| 项 | 内容 |
|---|---|
| 产品段 | 7 commits：`bf667b3`（服务端语义）/ `6ebe9ed`（客户端 UI）/ `a4d33cd`（文档口径）/ `6cbe4fc`（telemetry）/ `f2f3ba5`（披露）/ `21db990`（feature-flags）/ `866d4df`（测试注释）——**建议整段 revert 不拆分**（判别测试 tests/oauth-promotion.mjs 与语义 commits 成组；选择性 revert 会使台账与测试失配） |
| bump commit | E-1 产生的版本 commit（随回退一并 revert） |
| 治理段 | 治理 commits（0eb1324/820d862 等）——按 v0.3.0 C-3 先例保护：revert 后单独恢复（`git checkout <回滚前最新治理提交> -- .governance/`）或仅对产品代码路径执行 revert；**完整 commit 清单以 git log 实采为准**（执行前 `git log --oneline v0.3.0..HEAD` 复核实际拓扑） |

### B-2 顺序约束声明（本版特定——与 v0.3.0 的差异）

**v0.3.0 回滚方案的核心顺序约束（undici revert 不可单独于 OAuth 面执行）在本版不适用**：

- 事实依据：undici ^7.18.0 已随 v0.3.0 发布入库（FIX-006，CHANGELOG v0.3.0 节·修复）；v0.3.1 全部产品 commits 零触碰 package.json（EVO-006 R0 + REL-004 R0 两轮审查实采）；
- 推论：revert v0.3.1 产品段不触碰依赖声明——undici/peerDeps 与 v0.3.0 完全一致，不存在「回滚制造必败态」路径（推演级——基于发布事实 + 审查实采，§version-plan §7 #15）。

### B-3 版本面处置（按用户裁决二选一）

| 选项 | 动作 | 利 | 弊 |
|---|---|---|---|
| **a（默认建议）** | **前滚修复**：缺陷以 v0.3.2 热修承载（FIX-003/FIX-007 先例），已发布 tag/Release 不动；转正语义回退需求以代码修复实现（如恢复门控等价物） | 不动已发布面（已下载/已装用户零二次迁移）；热修先例成熟 | 缺陷修复需要新开发周期 |
| b | **整体回退重发**：revert + bump 至回退语义版（0.3.2）重新走 RG 门禁 + tag/push/Release；或删远端 tag `v0.3.1` + 删 GitHub Release 后重打 v0.3.1（GitHub 惯例允许）——**已下载/已装用户面需披露告知** | 版本面干净回到 v0.3.0 语义 | 已发布面变动需披露；重打 tag 对已装用户产生「同版本号不同内容」风险（选 0.3.2 回退版可避免） |

### B-4 验证

- 回滚后全量测试网复跑（对应基线形态——回退至 v0.3.0 语义则 smoke 基线回落至 v0.3.0 时点口径：934 ok/1 skip/0 fail，EV-078/084 权威）；
- tarball 重打包冷装（runbook 同 release-checklist-v0.3.1.md §冷装，断言版本号按回退版调整）；
- 判别测试形态：revert 后 tests/oauth-promotion.mjs 一并回退（「旧实验语义必败」断言随文件退场），无需兼容处理。

## 阶段三：用户侧安装态回退（无需 git 开发流程——分钟级）

### C-1 junction → 开发树形态（当前用户机实态——OPS-001，EV-069）

1. 开发树执行 `git checkout v0.3.0`（junction 指向开发树，检出版本即生效——OPS-001 升级路径语义的逆向使用）；
2. 重启 DSH（重启生效语义不变）。

### C-2 独立目录形态（重装路径）

1. 下载 v0.3.0 Release tarball（GitHub Release 在案——EV-084）→ 解压；
2. `install.ps1 -LocalPath .` / `install.sh --local .` 重装（或 README「固定版本」在线写法改回 `v0.3.0`）；
3. 重启 DSH。

### C-3 前置与回滚后行为

- **无强制登出前置**（数据兼容——见影响评估；v0.3.0 回滚方案 B-1 的「先行登出删除」强制前置在本版降级为可选项：仅当用户要求完全撤销凭据时先在 v0.3.1 执行「登出并删除凭据」）；
- **回滚后通道门控语义（推演级——基于 schemastery 透传实证 review-REL-004-R0 §四 + v0.3.0 发布语义）**：
  - 配置残留 `oauthExperimental` 键的用户（v0.3.0 时期曾开启/关闭过）：v0.3.0 schema 重新声明该键、**原值复活生效**——false = 通道关闭（入口隐藏 + 调用报「实验通路已关闭」）；true = 开启（ToS 已确认过则直达）；
  - 从未设置该键的新用户（v0.3.1 时期登录）：v0.3.0 缺省 false = **入口隐藏 + 通道受门控**——已落盘凭据保留但不可用；恢复使用 = 设置开启 `oauthExperimental` + ToS 确认；
- 验证：重启后设置页版本号/账号卡状态核对；统计页正常（数据面未变）。

## 场景 A：运行态止血（kill-switch 三层——转正后新语义，秒~分钟级）

| 层 | 操作 | 效果 | 验证语义 |
|---|---|---|---|
| ① 全局 | 设置 → Agent 路由 → `router.enabled=false` | route_agent 拒绝调用 + 提示段清空 + 统计暂停；配置与数据零删除 | ✅ **已验证**（smoke/routing-paths 既有断言——C13/D8b 看护；EV-086 复跑全绿） |
| ② 逐账号 | 账号卡片「停用账号」（`enabled=false`） | **调用与发起授权双侧拦截并明确提示**（resolveAgent 直连 + oauthBegin 发起，先于凭据触碰）+ 池选号跳过 + 发起拒绝留痕 `account_disabled` telemetry | ✅ **已验证**（oauth-promotion B1 直连拒绝零凭据副作用 / B2 发起拒绝留痕——13/13，EV-086） |
| ③ 撤销凭据 | 账号卡「登出并删除凭据」 | 删凭据文件 + 清 oauthAccounts 条目 + 清池引用；**恒可用不受任何开关门控** | ✅ **已验证**（文件不存在断言 + 登出×兑换竞态判别 + B4 双关闭态，EV-086） |

**边界注记**：模型发现（oauthDiscover）不受 ② 门控（管理面/使用面分界——feature-flags §4 注记）；**v0.3.1 无 flag 层**——v0.3.0 回滚方案场景 A-1（`oauthExperimental=false` 秒级止血）**已退役**，通道级全关 = ①层（`router.enabled`）。

**止血 vs 回滚决策**：关闭面 = 用户主权语义（谁不用关谁）——①/②/③层已覆盖「不用/停用/撤销」三档；仅当缺陷面超出关闭能力（如**启用态**账号调用本身故障、或升级兼容承诺②断裂）才进入阶段二代码层回滚。

## 影响评估

| 维度 | 评估 |
|---|---|
| 数据迁移 | 无——v0.3.1 零 Schema/数据格式变更；统计 JSONL 与凭据文件格式与 v0.3.0 完全一致（EVO-006/REL-004 无 stats/oauth-credentials 结构改动——审查实采） |
| 凭据文件 | v0.3.1 升级不触碰凭据（升级账号继续可用承诺）；回滚不删凭据（安全侧默认）；彻底撤销走场景 A-③ |
| 统计数据 | 零触碰——回滚无统计面影响（v0.3.0 回滚方案的统计清理步骤在本版不适用） |
| 用户配置 | 遗留键 `oauthExperimental`/`oauthTosAccepted` 在 v0.3.1 下被容忍透传（**用户配置文件中的键值零触碰**）——回滚至 v0.3.0 后该键重新被声明、原值复活生效（语义见 C-3，推演级）；其它配置键无变更 |
| telemetry | `account_disabled` reason 为 v0.3.1 新增——回滚后旧代码不产该事件；环形缓冲（上限 100）无格式冲突 |
| 回滚代价 | 丢失转正语义：通道回到「实验开关 + ToS 确认」门控；「开过又关」cohort 的关闭偏好在回滚后复活生效；UI 回到实验标签形态；新登录用户需重新走开关+ToS 流程 |
| 额外损失 | 无——revert/checkout 为机械操作（执行前确认工作区干净）；治理记录保护按 v0.3.0 C-3 先例 |
