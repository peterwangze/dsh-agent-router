# v0.2.0 回滚方案（Rollback Plan）

| 项 | 值 |
|---|---|
| 发布版本 | v0.2.0（2026-08-20） |
| 回滚目标 | v0.1.7（2026-08-17 tag） |
| 可逆性分类 | **可逆发布**——纯代码发布，无数据迁移、无 Schema 变更、无持久化存储改动 |
| 预计回滚时间 | **< 5 分钟**（单插件安装 / 单条 git 命令） |
| 关联文档 | `docs/release/release-checklist-v0.2.0.md`（第三步：回滚方案验证） |

---

## 回滚触发条件（发布后 48h 观察期）

1. 出现 P0/P1 级新 bug（回归、崩溃、核心通路失效）；
2. 端到端图片通路不可达（D-1-2 真实使用反馈：图片未到达视觉输入）；
3. `route_agent` 带图触发率首轮 U-3 统计 <90% 且无缓解手段（D-1-3）；
4. 用户主动要求回退。

## 场景 A：安装态回滚（用户侧，无需 git）

**步骤**：

1. 重新安装 v0.1.7：
   - **离线**：下载 `dsh-agent-router-v0.1.7.tar.gz` → 解压 → `powershell -ExecutionPolicy Bypass -File .\install.ps1 -LocalPath .`（Windows）/ `./install.sh --local .`（macOS / Linux）；
   - **在线**：安装命令中的版本固定位由 `main` 改为 `v0.1.7`（README「固定版本」写法）。
2. 重启 DSH。
3. 验证：带图消息行为回到 v0.1.7 形态（整轮路由机制恢复）；设置页「Agent 路由」配置仍在（agent / 账号配置存于 DSH settings，不随插件回滚丢失）。

## 场景 B：开发态回滚（仓库侧）

**步骤**：

1. 整段回退（二选一）：
   - **直接切 tag（首选，完全回到 v0.1.7）**：`git checkout v0.1.7`
   - **反转迁移提交**：`git revert c2648d2..53c0e40`（反转 v3 迁移 + 治理接入等迁移期全部提交；53c0e40 = Step 10 完结提交，c2648d2 = 迁移前基线。**注意：范围必须按正向书写 `c2648d2..53c0e40`（旧→新）——反向写法 `53c0e40..c2648d2` 在 git 语义下为空集，revert 不会执行任何提交**（发布审查 R-W3 修正，2026-08-20）；执行前建议 `git log --oneline v0.1.7..HEAD` 复核实际拓扑）
2. **注意事项（.governance/ 治理记录）**：迁移范围含治理接入提交（04f1e67 及后续治理记录），随 revert 会一并回退。如需保留治理记录仅回滚产品代码：revert 后单独恢复治理目录（`git checkout <迁移前最新治理提交> -- .governance/`），或仅对产品代码路径执行 revert。
3. 验证：`node tests/smoke.mjs` → 以 v0.1.7 基线断言形态全绿（v0.1.7 tag 处测试与产品代码同源，断言形态一致）。
4. 重发：回滚后如需重新发布 v0.2.0，撤销上述 revert（`git revert --no-commit` 反向执行）再走发布流程。

## 场景 C：kill-switch（总开关，无需回滚，立即止血）

- **操作**：设置 → Agent 路由 → 总开关 `router.enabled=false`。
- **效果**：`route_agent` 拒绝调用、统计暂停、路由提示不注入；配置与数据零删除。
- **已验证**：开关门控由 Step 3/6 自动化断言覆盖（EV-013 / EV-019）——关闭态零介入、恢复即还原（发布前 smoke 534 断言全绿证明）。
- **适用**：端到端问题排查、临时停用路由（不改变版本行为本身）。

## 影响评估

| 维度 | 评估 |
|---|---|
| 数据迁移 | 无——v2 → v3 全程零 Schema / 存储变更 |
| 缓存 | imageMemory 为进程内缓存（LRU + TTL），重启即清；回滚无残留 |
| 用户配置 | agent / 账号 / 统计配置存于 DSH settings（不随插件回滚）；统计为内存态（重启清零，与 v0.1.7 一致） |
| 工作区产物 | `.router-files/` 为用户上传文件落盘目录——回滚后不再生成新文件，已有文件保留，不参与回滚 |
| 回滚代价 | 丢弃 v0.2.0 全部行为变更与新能力（v3 迁移、任意文件上传、跨轮指代、附件统一寻址、三级展示等），回到 v0.1.7 旧机制（含其已知问题：整轮路由模型替换、历史图丢失 LP-1） |
| 额外损失 | 无——git revert / tag checkout 为机械操作，不触碰其他分支与未提交改动（执行前请确认工作区干净） |

## 验证方式汇总

| 维度 | 验证方式 | 状态 |
|---|---|---|
| 门控面（kill-switch） | smoke.mjs Step 3/6 断言（`router.enabled=false` 关闭态零介入 / 恢复即还原） | ✅ **已验证**（EV-013 / EV-019，发布前断言全绿） |
| git 层回滚 | 回滚后 `node tests/smoke.mjs`（v0.1.7 基线断言形态） | 程序化验证步骤已定义；回滚操作为机械 git 命令，观察期按需执行 |
| 安装态回滚 | v0.1.7 tarball 重新安装 + DSH 重启 + 行为核对 | 步骤已定义；与 v0.1.7 发布时已验证的离线安装流程一致 |

> 注：回滚方案"已验证"以门控面自动化断言为实证（总开关关闭态 = 零代码变更的立即止血面，发布前已由 Step 3/6 测试覆盖）；git / 安装态回滚为机械操作，验证程序（回滚后跑 v0.1.7 基线断言）已定义，观察期触发时按本方案执行并记录结果。
