## 回滚触发条件（发布后 48h 观察期）

1. 出现 P0/P1 级新 bug（回归、崩溃、核心通路失效）；
2. **FIX-009 修复失效**：image-solo 纯图消息 400/1213「未接收到prompt」复发（占位注入失效或引入新注入缺陷）；
3. **FIX-010 修复失效**：DEC-027 三不变量断裂——气泡图片再次消失 / 原始输入呈现被改写污染会话日志；
4. **EVO-007 数据主权缺陷**：删除路径失效 / 凭据清理不完整（P7——deleteOauthAccount 原子性破坏、孤儿条目残留）；R8-F1 判别断言组变红即触发；
5. 宿主 dsh-* 再漂移致适配断裂（RISK-003——parity 复跑变红即触发；本版零依赖变更，触发概率面与 v0.3.1 相同）；
6. 用户主动要求回退。

> 与 v0.3.1 触发条件的差异：v0.3.1 条件②（转正兼容承诺断裂——凭据保留/继续可用）与条件③（一键登录链路回归）**不列入本版**——v0.3.2 零 OAuth 通路语义变化（EVO-007 仅 UI 入口面；登录/凭据/兑换链路零触碰）；保留①②③④⑤⑥一般性条款。deepseek-official 视觉端点挂起（227s/0token）为宿主/端点域现象（vision 旁路 glm 可用，本仓不可修——EV-088）——**不构成本版回滚触发条件**，如实记录。**发布后 CHANGELOG 勘误惯例**沿用 v0.3.0/v0.3.1 先例（post-release 修正单独提交留痕，不重写已发布节历史）。

## 回滚总览（三阶段——先止血再动代码）

| 阶段 | 窗口 | 动作 | 生效 | 耗时 |
|---|---|---|---|---|
| 一 | push 前（执行段任一步失败/叫停） | 中止执行序列 + 本地清理 | 本地面 | 分钟级 < 5min |
| 二 | push 后（已 tag/已 Release） | 代码层 revert + 版本面处置（前滚修复或回退重发——用户裁决） | 版本面 | 15–30min |
| 三 | 用户侧（安装态） | junction 开发树 checkout v0.3.1 / v0.3.1 tarball 重装 + 重启 | 单机面 | 分钟级 |

## 阶段一：push 前 abort（发布执行中失败/叫停——分钟级）

执行序列（version-plan §4 M-5：E-1 bump → E-2 复跑 → E-3 pack+冷装 → E-4 tag → E-5 push → E-6 Release）在 **E-5 push 之前**任何一步失败或叫停时，按已完成步骤逆向清理：

| 已完成步骤 | 清理动作 | 验证 |
|---|---|---|
| E-1 bump commit（含 CHANGELOG v0.3.2 节创建收口/README 同步） | `git revert <bump-commit>`（**优先 revert 不用 reset**——保留历史留痕；仓内未推送无 force-push 顾虑） | `git log` 确认 revert 提交在案；package.json 回读 0.3.1 |
| E-3 pack + 冷装 | 删除仓库根 tgz；$tmp 临时目录清理（冷装 runbook 步骤已含零触碰校验） | 仓库根无 tgz 残留 |
| E-4 tag v0.3.2（本地） | `git tag -d v0.3.2` | `git tag -l v0.3.2` 为空 |
| E-2 复跑 | 无需清理（只读验证） | — |

**abort 窗口关闭点 = E-5 push 执行**。push 后进入阶段二。

## 阶段二：push 后代码层回滚（仓库侧——15–30 分钟）

### B-0 前置（顺序强制）

1. **先执行场景 A 止血**（kill-switch 关闭面——避免 revert 过程中缺陷面继续暴露）；
2. 评估缺陷范围：若缺陷可定位且前滚修复可行，**优先前滚**（B-3 选项 a）。

### B-1 revert 范围

| 项 | 内容 |
|---|---|
| 产品段 | 5 commits：`8877365`（FIX-009 wrapper 占位注入 + fix-009 判别测试）/ `020909b`（FIX-010 prestep header 优先 + fix-010 判别测试）/ `65226a3`（EVO-007 实现 + R8-F1 语义断言组）/ `3665d6a`（EVO-007 T1 返工——删除双入口 + 14 断言重写）/ `1d2bf36`（收尾段——P1-1 live default 对齐 + P2-2 hygiene + README）——**建议整段 revert 不拆分**（判别测试与语义 commits 成组：fix-010 tests 由 020909b 建立 + 1d2bf36 E 组扩展；fix-009 tests 由 8877365 建立 + 1d2bf36 hygiene 扩展；R8-F1 语义断言组随 65226a3/3665d6a；选择性 revert 会使台账与测试失配） |
| bump commit | E-1 产生的版本 commit（随回退一并 revert） |
| 治理段 | 治理 commits（d92dfba/ec94a6c/0c7f987/49ac8ab/0234a88/ed229db/b664f52/6877389 等）——按 v0.3.0/v0.3.1 C-3 先例保护：revert 后单独恢复（`git checkout <回滚前最新治理提交> -- .governance/`）或仅对产品代码路径执行 revert；**完整 commit 清单以 git log 实采为准**（执行前 `git log --oneline v0.3.1..HEAD` 复核实际拓扑——点名合计 13 vs ahead 12 差异一并消歧） |

### B-2 顺序约束声明（本版特定——与 v0.3.0 的差异，沿 v0.3.1 先例）

**v0.3.0 回滚方案的核心顺序约束（undici revert 不可单独于 OAuth 面执行）在本版不适用**：

- 事实依据：undici ^7.18.0 已随 v0.3.0 发布入库（FIX-006）；v0.3.1/v0.3.2 产品段均零触碰 package.json（v0.3.2 = review-REL-005-R0「无 bump」实证 + package.json 现态 0.3.1 实读）；
- 推论：revert v0.3.2 产品段不触碰依赖声明——undici/peerDeps 与 v0.3.1 完全一致，不存在「回滚制造必败态」路径（推演级——基于发布事实 + 审查实采，version-plan §7 #9）。

### B-3 版本面处置（按用户裁决二选一）

| 选项 | 动作 | 利 | 弊 |
|---|---|---|---|
| **a（默认建议）** | **前滚修复**：缺陷以下一版本承载（0.3.3 或独立热修版本——FIX-003/FIX-007 先例），已发布 tag/Release 不动 | 不动已发布面（已下载/已装用户零二次迁移）；热修先例成熟 | 缺陷修复需要新开发周期 |
| b | **整体回退重发**：revert + bump 至回退语义版（0.3.3）重新走 RG 门禁 + tag/push/Release；或删远端 tag `v0.3.2` + 删 GitHub Release 后重打 v0.3.2（GitHub 惯例允许）——**已下载/已装用户面需披露告知** | 版本面干净回到 v0.3.1 语义 | 已发布面变动需披露；重打 tag 对已装用户产生「同版本号不同内容」风险（选 0.3.3 回退版可避免） |

### B-4 验证

- 回滚后全量测试网复跑（对应基线形态——回退至 v0.3.1 语义则基线回落至 v0.3.1 时点口径：smoke 948 ok/0 fail/exit 0，EV-086 权威 + 收尾段前形态）；
- tarball 重打包冷装（runbook 同 release-checklist-v0.3.2.md §冷装，断言版本号按回退版调整）；
- 判别测试形态：revert 后 tests/fix-009-image-solo.mjs 与 tests/fix-010-gui-fidelity.mjs 随产品段**一并回退**（含 E 组 4 断言与 R8-F1 语义断言组——整段 revert 保证实现与断言同退，无失配），无需兼容处理。

## 阶段三：用户侧安装态回退（无需 git 开发流程——分钟级）

### C-1 junction → 开发树形态（当前用户机实态——OPS-001，EV-069）

1. 开发树执行 `git checkout v0.3.1`（junction 指向开发树，检出版本即生效——OPS-001 升级路径语义的逆向使用）；
2. 重启 DSH（重启生效语义不变）。

### C-2 独立目录形态（重装路径）

1. 下载 v0.3.1 Release tarball（GitHub Release 在案——EV-087）→ 解压；
2. `install.ps1 -LocalPath .` / `install.sh --local .` 重装（或 README「固定版本」在线写法改回 `v0.3.0`→`v0.3.1`）；
3. 重启 DSH。

### C-3 前置与回滚后行为

- **无强制登出前置**（数据兼容——见影响评估；本版零 OAuth 通路语义变化，凭据/账号数据零触碰）；
- **回滚后行为（推演级——基于 v0.3.1 发布事实 EV-087 + 本版变更范围）**：
  - **FIX-009/FIX-010 修复失效回退**：image-solo 纯图消息回到 v0.3.1 缺陷态（空 content → 400/1213——**仅当用户环境再次触发 image-solo 纯图消息时暴露**）；气泡显示回回归缺陷态（**仅当漂移窗口命中**——无 header + options 快照偏离 live default）；两处均非持续可见，触发面以真实使用为准；
  - **EVO-007 布局回退**：「OAuth 账号（官方登录）」不可用入口在 v0.3.1 下**复活可见**（README「v0.3.2 起移除」声明与回滚后界面不一致——需披露告知）；ChatGPT 订阅登录回到子代理之下原位置；
  - **删除路径回退**：非 preset OAuth 账号删除路径回到 v0.3.1 形态（池行「移除」**不清凭据**——F-1 缺陷面在 v0.3.1 存在，P7 数据主权风险复活；彻底撤销凭据需走 v0.3.1 的「登出并删除凭据」（preset 面）或手动清理）——**回滚代价如实披露**；
  - 数据面：凭据/账号条目/统计 JSONL 零变化（本版零触碰）。
- 验证：重启后设置页版本号/账号面板布局核对；统计页正常（数据面未变）。

## 场景 A：运行态止血（kill-switch 三层——v0.3.2 无 flag 变化，与 v0.3.1 同语义，秒~分钟级）

| 层 | 操作 | 效果 | 验证语义 |
|---|---|---|---|
| ① 全局 | 设置 → Agent 路由 → `router.enabled=false` | route_agent 拒绝调用 + 提示段清空 + 统计暂停；配置与数据零删除 | ✅ **已验证**（smoke/routing-paths 既有断言——C13/D8b 看护；EV-090 12 套件全绿） |
| ② 逐账号 | 账号卡片「停用账号」（`enabled=false`） | **调用与发起授权双侧拦截并明确提示**（resolveAgent 直连 + oauthBegin 发起，先于凭据触碰）+ 池选号跳过 + 发起拒绝留痕 `account_disabled` telemetry | ✅ **已验证**（oauth-promotion B1 直连拒绝零凭据副作用 / B2 发起拒绝留痕——13/13，EV-090） |
| ③ 撤销凭据 | 池行「删除账号」/ 孤儿列表删除（**v0.3.2 双入口**）/ 「登出并删除凭据」 | 删凭据文件 + 清 oauthAccounts 条目 + 清池引用；**恒可用不受任何开关门控** | ✅ **已验证**（文件不存在断言 + 登出×兑换竞态判别 + B4 双关闭态 + R8-F1 可删语义断言组——EV-090） |

**边界注记**：模型发现（oauthDiscover）不受 ② 门控（管理面/使用面分界——feature-flags §4 注记沿用）；**v0.3.2 无 flag 层变化**——通道级全关 = ①层（`router.enabled`）；③层入口形态为 v0.3.2 增强（双入口共用 deleteOauthAccount 原子提交），语义不变。

**止血 vs 回滚决策**：关闭面 = 用户主权语义（谁不用关谁）——①/②/③层已覆盖「不用/停用/撤销」三档；仅当缺陷面超出关闭能力（如**启用态**账号调用本身故障、FIX-010 气泡呈现缺陷持续、或删除路径原子性破坏——P7）才进入阶段二代码层回滚。

## 影响评估

| 维度 | 评估 |
|---|---|
| 数据迁移 | 无——v0.3.2 零 Schema/数据格式变更；统计 JSONL 与凭据文件格式与 v0.3.1 完全一致（EVO-007 oauthAccounts 数据域零触碰——EV-090；FIX-009/010 纯判定/改写面） |
| 凭据文件 | v0.3.2 升级不触碰凭据；回滚不删凭据（安全侧默认）；彻底撤销走场景 A-③（v0.3.2 双入口）或 v0.3.1 形态（preset 登出删除） |
| 统计数据 | 零触碰——回滚无统计面影响 |
| 用户配置 | settings 遗留键（oauthExperimental/oauthTosAccepted）在 v0.3.2 继续容忍透传（本版零 schema 变更——零触碰）；回滚无影响 |
| telemetry | 本版零 telemetry 事件变化（FIX-009 占位注入 P8 无吞错——无新事件；EVO-007 无埋点变更）；回滚后无新旧格式冲突（环形缓冲上限 100 沿用） |
| 回滚代价 | 丢失双修复（image-solo 纯图 400 缺陷态 + 气泡显示回归缺陷态——触发面以真实使用为准）+ EVO-007 布局回退（不可用入口复活可见——README 披露与界面不一致需告知）+ **删除路径回 v0.3.1 形态（F-1 缺陷面复活——P7 数据主权风险，如实披露）** + P1-1 回落层对齐失效（漂移窗口分裂面回 v0.3.1 现状） |
| 额外损失 | 无——revert/checkout 为机械操作（执行前确认工作区干净）；治理记录保护按 v0.3.0/v0.3.1 C-3 先例 |
