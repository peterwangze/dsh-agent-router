# 项目质量与工程原则（project-principles）

> **版本**: P-v1（2026-08-20 立版）· **来源**: 用户会话指令（/governance 2026-08-20 恢复面板自定义答复，DEC-016 入账 / GOV-001 执行）
> **性质**: 本项目全部任务（分析/设计/实现/修复/发布）的强制行为准则。与治理工作流（software-project-governance）叠加生效；两者冲突时以更严格者为准。
> **权威源**: 本文件。AGENTS.md「项目质量原则」段为其会话级投影；修改以本文件为准并同步投影。

## 一、原则（7 条）

| # | 原则 | 执行锚点（本项目既有机制 / 先例） |
|---|------|----------------------------------|
| P1 | 分析和推演需要基于事实，不允许假设和编造 | evidence-log 证据链；V-DSH 待验证清单（无实证不泛化——DEC-014 先例）；not-measurable 不编造（EV-023 metrics 红线） |
| P2 | 实现需要进行全面的分析，避免修改遗漏 | 变更影响分析（change-impact 五步）；架构 §8 分步迁移路径（依赖链显式化）；Reviewer 设计一致性逐项核验 |
| P3 | 实现需要考虑对原有功能的影响，避免引入新问题 | 回归断言零回退纪律（534 smoke 基线）；每次审查含"既有断言全部保持"核验（EV-011~023 通例） |
| P4 | 实现需要进行测试看护，构建防护网，避免后续问题反复 | DEV-002（核心通路自动化测试补强）；RISK-001（CI 缺口跟踪）；tests/metrics.mjs 31 项观测；返工后必须复跑全量（EV-014/021 先例） |
| P5 | 实现需要考虑泛化性，严禁单点修改 | DEC-005 通用附件路由框架（模态无关设计）；M2 统一编址层（非图片特化）；模态矩阵 audio/video 留位（Step 7） |
| P6 | 以高质量交付为准则，严禁为了完成任务而忽略质量 | Gate 体系（G1-G7）；独立审查链（R1-R14，含两次 NEEDS_CHANGE→返工→复审闭环先例）；D-1 验收门；关闭规则"P1 有遗留计划→有条件通过" |
| P7 | 修复要保证安全性，避免引入导致损坏用户数据的情况 | fail-closed 边界（R12 F-1 符号链接逃逸防护）；内容寻址完整性校验（sha256 往返，EV-017）；O_EXCL 写入不覆盖 + 碰撞去重（R10 F-02） |

## 二、编程要求（4 条）

| # | 要求 | 执行锚点 |
|---|------|---------|
| C1 | 设计需要考虑可扩展性和可维护性，需要基于未来进行设计 | imageMemory 全局作用域（DEC-012 D-5）；audio/video 模态占位（Step 7）；W-5 双轨兼容期（大版本再严格化） |

| C3 | 实现需要保证模块/类/接口的职责单一，避免引入上帝类/上帝模块和多功能接口 | DEC-011：编址层选独立模块 lib/attachments.js 而非并入 service.js；M1-M6 模块划分无循环依赖（architecture-v3 §3） |
| C4 | 实现不要搞任何冗余的修改，保持修改的纯粹性，一个 commit 承载一个问题修改/功能实现 | MIG-001 Step 0-10 每步独立提交 + 测试全绿模式；审查范围合规核验（git show --stat 恰 N 文件，F-3 通例） |

## 三、落地机制（如何在会话中生效）

1. **AGENTS.md 投影**：DSH 每会话自动注入「项目质量原则」段（本文件为权威源，投影仅为携带通道）
2. **会话 bootstrap**：读取 plan-tracker 时经版本规划纪律条款引用本文件（发布复盘演进检查）
3. **审查检查面**：Code/Design Reviewer 将本原则表纳入审查维度——违反原则的实现 MUST 在审查结论中标注违反条目（如 `P4-violation`、`C4-violation`）
4. **执行包约束**：活跃产品代码任务的 execution-packet 应引用相关原则条目作为完成定义的一部分（Check 18c 范围校验）

## 四、持续改进与扩充约定

1. **演进时机**：复盘会议（阶段 11）/ Gate 评审 / 任何会话中用户或 Reviewer 提出
2. **入账协议**：新增或修改原则 → decision-log 记录（DEC-xxx，含理由与影响面）→ 本文件更新（P-v1 → P-v2，变更历史表追加）→ AGENTS.md 投影同步
3. **质量基线只升不降**：任何修改不得削弱既有原则的约束力；替换条目需给出等价或更强的约束
4. **扩充方向（候选，按需入账）**：性能基线、可观测性规约、文档规约、安全审计清单
5. **复盘强制检查**：每次版本发布复盘时 MUST 检查本文件是否需要演进（plan-tracker 版本规划纪律已挂钩）
